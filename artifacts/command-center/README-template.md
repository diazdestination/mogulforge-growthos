# MogulForge GrowthOS — client export reference

This is the README copied into a client export by the legacy product-export
script. It is not the canonical GrowthOS product README or a declaration that a
fresh export is deployed or accepted for a contractor.

The maintained product is
[diazdestination/mogulforge-growthos](https://github.com/diazdestination/mogulforge-growthos).
Read its [current build](https://github.com/diazdestination/mogulforge-growthos/blob/main/CURRENT-BUILD.md)
and [documentation map](https://github.com/diazdestination/mogulforge-growthos/blob/main/docs/DOCUMENTATION-MAP.md)
for the current feature inventory and source/live distinction. These absolute
links also work when this document is copied to an exported repository root.

## What the maintained product contains

The canonical application uses React/Vite, an Express API and PostgreSQL/Drizzle.
It includes contractor customer/property work, scheduling, estimates/jobs/
invoices, service follow-up, BIE, website capture and controlled communication
foundations. The exact exported artifact must be inspected and tested on its
own source/package/configuration set before making equivalent feature claims.

## Client preparation

Inspect the actual client branding/configuration files, dependencies, domain,
organization boundaries, authentication and storage before changing or deploying
an export. Preserve approved artwork and existing client data. Do not invent
business names, staff phones, terms, warranties or credentials.

Per-client sending, phone routing, registration, provider credentials and handset
acceptance are separate requirements. A template business name or a copied
callback path does not activate Twilio, email or an AI phone agent.

## Export and update boundary

The legacy scripts describe an explicit export/sync operation, which can replace
the destination history. It is not an automatic update mechanism for the
canonical GrowthOS application. Do not activate a staged sync workflow or run
the export/push script merely because this README was copied into a repository.
Verify source/destination/account, preserve destination work and obtain the
applicable reviewed distribution authority first.

Build/release instructions belong to the exact selected source and its reviewed
deployment/recovery plan. Do not assume Replit authentication, the older Painless
template, a generic schema push or a bare provider deploy command is the current
product's deployment contract. Source tests, live providers and full contractor
acceptance must each retain their own evidence.
